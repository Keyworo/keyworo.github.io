1 文档信息

目标读者：博卡产品团队、技术开发团队、阿里云集成团队、业务决策者

项目背景

博卡作为领先的美容美发SaaS软件提供商，当前预约流程高度依赖人工客服（如电话接听、短信提醒），导致以下问题：

  • 效率低下：高峰期人工客服响应延迟，预约转化率低（行业平均约60%）。
  • 成本高企：人工处理预约占客服成本的40%，且易出错（如信息记录遗漏）。
  • 客户体验差：消费者等待时间长，临近预约无主动提醒，导致爽约率高达25%。

为提升竞争力，博卡计划整合阿里云电话语音服务（基于智能语音交互ASI）和AI大模型（通义千问Qwen），构建AI电话预约机器人，实现自动化、智能化的预约管理。

3 产品概述

产品描述

博卡AI电话预约机器人是一款基于云的智能语音交互系统，利用阿里云智能语音交互（ASI）服务和通义千问大模型，实现：

呼入场景

消费者拨打博卡统一预约号码（如400-XXX-XXXX），AI自动应答，通过自然对话理解意图、收集预约信息，并实时同步至博卡SaaS数据库。

呼出场景

系统在预约时间前24小时主动外呼，发送个性化提醒，并根据消费者反馈更新预约状态。

SaaS集成

产品作为博卡SaaS的增值模块，面向所有签约美容美发门店客户开放（按门店订阅收费）。

目标用户

用户角色 描述 核心需求
终端消费者 美容美发店客户（如预约剪发、染发的个人） 快速完成预约、接收及时提醒、减少等待
门店管理员 美容美发店老板或店长（博卡SaaS用户） 降低人工成本、提高预约确认率、减少爽约
博卡运维团队 博卡内部技术支持人员 系统稳定、易配置、数据安全

核心价值主张

对消费者
  • 7×24小时即时响应，告别等待
  • 个性化语音提醒，提升服务体验
对门店
  • 自动化处理80%+预约请求，释放人力
  • 数据驱动决策（如分析爽约原因）
对博卡
  • 增强SaaS产品粘性
  • 创造新收入来源（高级版订阅费）

4 呼入电话处理功能

关键依赖：阿里云智能语音交互（ASI）提供实时语音识别（ASR）、语音合成（TTS）；通义千问大模型用于意图识别与对话生成

电话接入与初始应答

触发条件：消费者拨打博卡分配的预约号码（需在阿里云控制台配置虚拟号码）

1
电话接入
消费者拨打400预约号码
2
AI应答
3秒内播放欢迎语
3
ASR启动
实时语音转文字

系统行为：

  • 接通后3秒内，AI使用TTS播放欢迎语（示例："您好！欢迎致电博卡美容美发预约中心。我是智能助手小美，请问您需要预约服务、查询订单，还是其他帮助？"）
  • 支持阿里云ASI的静音检测，避免背景噪音干扰

需求细节： 欢迎语需支持个性化定制（门店可上传品牌语音包）；初始应答后启动ASR实时转写（阿里云ASR准确率≥95%，针对中文方言优化）

意图识别与对话管理

核心逻辑：通义千问大模型分析ASR转写文本，识别消费者意图（分类准确率≥90%）

意图类型 触发关键词示例 系统响应流程
预约 "我想预约"、"剪头发"、"明天有空吗" 引导式对话收集信息（见下文）
取消 "取消预约"、"改时间" 确认预约ID → 询问原因 → 更新状态
查询 "查预约"、"我的订单" 验证手机号 → 播报最近预约详情
其他 无法识别的语句 提供3次重试机会 → 转人工客服

AI模型要求： 使用通义千问行业精调版；支持上下文记忆；错误处理：当置信度<80%时，AI主动澄清

预约信息收集与记录

系统通过对话动态收集以下必填字段：

字段 收集方式 验证规则
客户姓名 语音询问 → ASR转写 非空，长度2-20字符
电话号码 语音询问 → ASR转写 标准11位手机号，阿里云号码验证API校验
服务类型 提供选项：剪发/染发/护理/其他 从博卡SaaS服务库动态拉取
预约日期时间 询问偏好 → 提供可用时段 仅允许选择门店空闲时段
门店ID 询问或默认最近消费门店 从客户历史记录自动填充
理发师偏好 可选询问 从SaaS理发师库匹配
对话示例

消费者：我想预约明天的剪发。

AI：好的，请问您的姓名是？

消费者：张三。

AI：张三先生/女士，您的手机号码是？

消费者：13800138000。

AI：正在查询明天可用时段... 上午10点或下午3点，您方便哪个时间？

消费者：下午3点。

AI：已为您预约明天下午3点剪发服务，门店为"博卡旗舰店"。预约ID：BKB20231027001。需要其他帮助吗？

5 呼出提醒功能

触发与调度逻辑

触发条件：

  • 预约状态为"已确认"
  • 距预约时间≤24小时（可配置，门店可在SaaS后台调整提前量：12h/24h/48h）

调度规则：

  • 每日08:00-20:00执行外呼（避免夜间打扰）
  • 阿里云语音通知服务自动排队，支持每小时1000+并发呼叫
  • 失败重试：首次未接通 → 2小时后重试 → 最多3次

呼出交互流程

基础流程：

  1. 拨通后TTS播报提醒（示例："张三先生/女士，您预约的博卡旗舰店剪发服务在明天下午3点。请准时到店，回复1确认，2改期，3取消。"）
  2. 消费者按键/语音反馈 → AI处理响应
  3. 更新预约状态至SaaS系统
消费者反馈 系统行为
确认(1) 播放成功提示 → 状态更新为"已提醒"
改期(2) 引导重新选择时间 → 生成新预约ID
取消(3) 询问原因 → 状态更新为"已取消"
无响应 播放短信提醒提示 → 记录为"未确认"

AI增强点： 通义千问生成个性化话术；动态调整提醒内容（如集成天气API）

状态同步与通知

数据闭环：

  • 消费者确认后，调用博卡API更新预约状态
  • 爽约预警：若消费者未确认且临近预约时间 → 自动推送门店APP通知
  • 报表生成：每日生成提醒报告（确认率、取消率），供门店在SaaS后台查看

6 系统集成需求

与博卡SaaS集成

集成点 接口说明 协议/格式
预约数据同步 呼入/呼出时创建/更新预约记录 REST API (JSON)
门店空闲时段查询 AI收集预约时间时，实时查询可用时段 GET /api/slots
客户历史记录获取 呼出时调取客户姓名、历史服务偏好 GET /api/customers
状态变更通知 预约状态更新后，触发SaaS内部工作流 Webhook

与阿里云服务集成

阿里云服务 配置要求
智能语音交互(ASI) - 开通实时语音识别（ASR）和语音合成（TTS）
- 配置虚拟号码池（支持10+并发）
通义千问(Qwen) - 部署行业精调模型（需提供博卡训练数据）
- 设置API调用限流（50QPS）
语音通知服务 - 预审核外呼模板（避免违规）
- 配置OSS存储通话录音
安全服务 - 启用RAM角色权限控制
- 通话数据传输使用HTTPS+TLS 1.3

7 非功能需求

性能需求

  • 响应时间：ASR转写≤1.5秒，AI意图识别≤0.5秒，端到端对话响应≤2秒（P95）
  • 并发能力：支持单门店50+并发呼叫（阿里云ASI可弹性扩容）
  • 可靠性：系统可用性≥99.9%，故障自动切换至备用线路

安全与合规

  • 数据隐私：通话录音和客户信息加密存储（阿里云KMS密钥管理）
  • 合规要求：符合《个人信息保护法》，外呼前需消费者授权
  • 安全审计：记录所有API调用日志，支持等保2.0三级要求

可维护性

  • 配置化管理：门店可在SaaS后台自定义话术模板、外呼时间窗口
  • 监控告警：集成阿里云ARMS，实时监控ASR错误率、呼叫成功率
  • 日志记录：详细记录通话流程，便于问题排查和AI优化

兼容性

  • 设备支持：适配主流手机（iOS/Android）和固话
  • SaaS版本：兼容博卡当前所有SaaS版本（v3.0+）
  • 网络环境：支持4G/5G/WiFi等多种网络环境

8 用户场景示例

场景1：消费者呼入预约（新客户）

背景：李女士首次预约，拨打博卡400号码。

流程：

  1. AI接通：播放欢迎语 → 识别"预约"意图
  2. 对话：
    • AI：请提供姓名？ → 李女士：李四。
    • AI：您的手机号？ → 李女士：13900139000。
    • AI：需要什么服务？（选项：剪发/染发/护理） → 李女士：染发。
    • AI：查询到"博卡朝阳店"明天15:00有空位，可以吗？ → 李女士：可以。
  3. 结果：系统生成预约ID BKBJ20231027002，短信发送确认信息
场景2：系统呼出提醒（临近预约）

背景：王小姐预约了明天10:00剪发，系统提前24小时外呼。

流程：

  1. 外呼接通：AI播报提醒 → 王小姐按键"1"确认
  2. 系统：更新状态为"已确认"，记录确认时间
  3. 异常：若王小姐说"改到后天"，AI引导重新选时间 → 生成新预约
